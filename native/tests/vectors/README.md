# Exact-state test vectors

Every file here is generated by a `tools/generate_*` script from pinned, public
reference models in the research repository
(`github.com/Open-Champions/champions-return-to-arms-re`); none is native
output and none contains game bytes. The `.json` manifest beside each corpus
records its research commit, the SHA-256 of every pinned reference file, and
the SHA-256 of the corpus, so a regenerated file is checked before any test
uses it.

## Corpora that are not committed

The repository keeps no file larger than 5 MB. These corpora are therefore
generated locally; their manifests are committed. Until a corpus exists, its
CTest entry is registered but disabled ("Not Run (Disabled)", see the end of
`native/CMakeLists.txt`) and the matching Python provenance test is skipped.

`RESEARCH` below is a local clone of the research repository; each generator
reads its pinned commit with `git show`, so the checkout itself may be on any
branch, but the commit must be present (`git fetch --all`).

|---|---|---|

| `script_builtins.tsv.gz` | `script-builtins-exact` | `python3 -I tools/generate_script_builtins_vectors.py --research-dir "$RESEARCH"` |
| `player.tsv.gz` | `player-exact` | `python3 -I tools/generate_player_vectors.py --research-dir "$RESEARCH"` |
| `monsters_1.tsv.gz` | `monsters-1-exact` | `python3 -I tools/generate_monsters_1_vectors.py --research-dir "$RESEARCH" --output native/tests/vectors/monsters_1.tsv.gz` |

| `skills_c.tsv.gz` | `skills-c-exact` | `python3 -I tools/generate_skills_c_vectors.py --research-dir "$RESEARCH" --output native/tests/vectors/skills_c.tsv.gz` |

Re-run CMake configure after generating, so the test is enabled again. Check
each generator's `--help` for further options; several pinned commits live on
`t3/research-*` branches rather than on `main`.

Do not commit a regenerated corpus that is over 5 MB.
